# Code of conduct

## The standard

This project is a technical workspace. Behave the way a good colleague behaves in a code review:
address the work, not the person; assume competence; explain reasoning; accept being wrong without
drama.

Specifically, these are expected:

- **Critique the artifact.** "This gate fails open when the input is empty" is useful. "This is
  sloppy work" is not.
- **Be direct.** Softening a real problem until it disappears helps nobody. Say the thing.
- **Show your evidence.** Assertions about behaviour should come with a file, a line, or a command
  someone else can run.
- **Accept a decision once it is made**, or take the disagreement to a new issue. Re-litigating in
  every thread is a form of obstruction.
- **Respect that maintainer time is finite.** An unanswered issue is usually a queue, not a slight.

These are not acceptable:

- Personal attacks, demeaning comments, or sustained hostility.
- Harassment of any kind, in the repository or in venues connected to it.
- Publishing someone's private information.
- Deliberately submitting content the author knows to be unverified, plagiarised, or unsafe.

## Scope

Applies to issues, pull requests, discussions, commit messages and any space where someone is
representing this project.

## Enforcement

Report a problem through https://federicocalo.dev or by private GitHub message to the maintainer.
Reports are read by the maintainer and kept confidential.

Responses, in escalating order: a private clarification; a public correction in the thread; editing
or removing the content; a temporary block; a permanent block. The response is chosen to fit what
happened, and the reasoning is given to the person concerned.

The maintainer is subject to this policy on the same terms as everyone else.

## On adopting a standard text instead

This is an original, deliberately short policy. Projects that prefer a widely recognised text may
adopt the [Contributor Covenant](https://www.contributor-covenant.org/) instead; it is not
reproduced here.
